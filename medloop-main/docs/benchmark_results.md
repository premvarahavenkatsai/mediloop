# MedLoop Index Benchmark Results (`docs/benchmark-results.md`)

> **How This File Is Generated**: Run `python -m scripts.benchmark` after seeding your MongoDB instance (`python -m scripts.seed`). The script programmatically drops and rebuilds each index on `devices` and `events`, executes MongoDB `explain("executionStats")` before and after, and overwrites this file with the exact runtime metrics from your local MongoDB Community Server or MongoDB Atlas M0 cluster. No numbers are hardcoded or fabricated prior to running against a live `mongod` instance.

## Command to Populate Live Metrics

```bash
python -m db.setup
python -m scripts.seed
python -m scripts.benchmark
```

## Why Each Benchmark Query Behaves This Way

1. **Query (a) — Compound Equality Filter (`{category: 1, status: 1}`)**:
   - Without `idx_devices_category_status`, MongoDB performs a full `COLLSCAN` across all 2,000 device documents.
   - With `idx_devices_category_status`, MongoDB traverses only the matching `(category, status)` B-tree leaf range (`IXSCAN`).
2. **Query (b) — ESR Rule on Append-Only Events (`{device_id: 1, ts: -1}`)**:
   - Without `idx_events_device_id_ts_desc`, MongoDB scans all 50,000+ event documents (`COLLSCAN`) and executes an in-memory blocking `SORT` stage.
   - With `{device_id: 1, ts: -1}`, the equality prefix `device_id` isolates the single device's events and `ts: -1` delivers them already ordered newest-first (`IXSCAN` with no `SORT` stage).
3. **Query (c) — Full-Text Search (`name`, `notes`)**:
   - Without `idx_devices_name_notes_text`, searching across `name` and `notes` via `$regex` requires examining every document in `devices` (`COLLSCAN`).
   - With the compound `TEXT` index, MongoDB uses an inverted-index lookup (`TEXT_MATCH` over `IXSCAN`) on tokenized stems.
4. **Query (d) — Spherical Geospatial Filter (`$geoWithin` + `$centerSphere`)**:
   - `$geoNear` fails immediately if no `2dsphere` index exists on the collection. Using `$geoWithin` with `$centerSphere` allows a fair before/after comparison: without `idx_devices_location_2dsphere`, MongoDB computes spherical distance across every document via `COLLSCAN`; with the `2dsphere` index, it narrows candidates using S2 geometry cells via `IXSCAN`.
5. **Query (e) — Covered Query (`projection={"category": 1, "status": 1, "_id": 0}`)**:
   - Because all filter fields and all projected fields are contained inside `idx_devices_category_status` and `_id` is explicitly excluded (`_id: 0`), MongoDB's WiredTiger engine answers the query solely from the index (`totalDocsExamined = 0`).
